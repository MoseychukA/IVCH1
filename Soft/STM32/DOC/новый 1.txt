Ниже — проверка вашего .ino на ошибки компиляции/логики и что нужно поправить. В целом структура корректная,но есть несколько проблем,которые почти наверняка дадут ошибки или некорректную работу.

1) Явные ошибки / потенциальные ошибки компиляции
1.1. Опечатка в Serial.println("AT24C128 found (0x50");
Не закрыта скобка/кавычки. Должно быть,например:

cpp Копировать
Serial.println("AT24C128 found (0x50)");
1.2. fmod() и isnan() — нужен <math.h>
У вас используется fmod() и isnan(),но <math.h> не подключён. Часто “случайно” тянется,но лучше явно:

cpp Копировать
#include <math.h>
1.3. dtostrf — возможна ошибка “redefinition”
На STM32 dtostrf часто уже определён. Ваше определение может вызвать ошибку линковки/компиляции.

Решение:обернуть:

cpp Копировать
#ifndef dtostrf
char* dtostrf(double val, signed char width, unsigned char prec, char* sout) {
  sprintf(sout, "%*.*f", width, prec, val);
  return sout;
}
#endif
(или просто удалить вашу функцию,если всё и так собирается).

1.4. Sd2Card / SdVolume / SdFile + #include <SD.h>
Классы Sd2Card, SdVolume, SdFile обычно относятся к SdFat (или “utility” внутри старого SD),и в современных сборках могут не быть доступны через <SD.h>.

Если SD_setup() вам сейчас не нужен — самый простой вариант: закомментировать эти объявления и сам SD_setup().

Если нужен — подключайте правильную библиотеку (SdFat) и соответствующие include’ы.

2) Конфликты пинов (важно)
2.1. SW4_PIN и BUTTON_PIN — оба PC0
cpp Копировать
#define SW4_PIN PC0
#define BUTTON_PIN PC0
Это не ошибка компиляции,но логически:

btnSW4 и антидребезг digitalRead(BUTTON_PIN) читают одну и ту же кнопку.
Если так задумано — ок,но тогда “кнопка частоты” и “фиксация” в меню будут конфликтовать по назначению.
Если не задумано — назначьте разные пины.

2.2. Для кнопок не задан режим входа (pull-up/pull-down)
У вас есть Button-класс,он может сам настраивать,но для BUTTON_PIN вы делаете digitalRead() напрямую и нигде не делаете pinMode(PC0, INPUT_PULLUP).

Если кнопка на землю — обычно нужно:

cpp Копировать
pinMode(BUTTON_PIN, INPUT_PULLUP);
3) Лишнее/неиспользуемое (не критично,но лучше почистить)
Дубликаты:
cpp Копировать
#include <Arduino.h>
#include <Arduino.h>
достаточно одного.
SIM800TimeAsync::NtpConfig ntp; глобальный — нигде не используется (в applyCfgToSim создаётся локальный ntp).
Большой блок функций UTC (daysFromCivil/.../localToUTC) сейчас нигде не используется — можно удалить,чтобы не раздувать скетч и не путать.
4) Корректность интеграции SIM800 + EEPROM + TimeFeed
4.1. TimeFeed.h корректен только если есть TimeFeed.cpp
Вы используете:

cpp Копировать
snprintf(gDateStr, sizeof(gDateStr), ...);
Это скомпилируется только если в проект добавлен TimeFeed.cpp,где определены gDateStr/gTimeStr/gTimeUpdated. Иначе будет ошибка линковки “undefined reference”.

4.2. Применение настроек из EEPROM
ee.load(cfg,false); — вы не проверяете возвращаемое значение. Это нормально,т.к. load(false) у нас задумывался как “best effort”,но имейте в виду:если EEPROM пустая/мусор,внутри load должны остаться дефолты. (В моей реализации так и сделано.)

5) Минимальный патч прямо в ваш .ino
Добавьте вверху:

cpp Копировать
#include <math.h>
#ifndef dtostrf
char* dtostrf(double val, signed char width, unsigned char prec, char* sout) {
    sprintf(sout, "%*.*f", width, prec, val);
    return sout;
}
#endif
Исправьте строку:

cpp Копировать
Serial.println("AT24C128 found (0x50)");
И добавьте настройку кнопки (если используете digitalRead(BUTTON_PIN) напрямую):

cpp Копировать
pinMode(BUTTON_PIN, INPUT_PULLUP); // если кнопка замыкает на GND
6) Рекомендация по структуре loop()
У вас sim.tick() вызывается один раз в начале — это правильно. Главное — не добавлять длинных delay() (сейчас закомментировано). Учтите:ваш rtc.setTime() внутри RTCSupport содержит несколько delay(500) (если вы его не меняли) — это будет подвешивать цикл. Если вы хотите полностью неблокирующую работу,нужно убрать эти задержки из setTime().

какая SD-библиотека реально используется (стандартная SD или SdFat),
должна ли кнопка PC0 быть одной на всё или разной для меню/частоты,
я дам “чистую” версию .ino без конфликтов и с гарантированной компиляцией под ваш набор библиотек.
