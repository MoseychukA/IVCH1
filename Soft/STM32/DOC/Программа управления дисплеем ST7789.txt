Микроконтроллер STM32F103VGT6
Среда программирования Arduino IDE с STM32GENERIC  https://github.com/danieleff/STM32GENERIC


Для работы с дисплеем ST7789 SPI 170x320 в среде Arduino IDE с STM32GENERIC на микроконтроллере STM32F103VGT6 отлично подойдет популярная и активно поддерживаемая библиотека Bodmer/TFT_eSPI:

1. TFT_eSPI (Bodmer)
URL:
GitHub - Bodmer/TFT_eSPI: Arduino and PlatformIO IDE compatible TFT library optimised for the Raspberry Pi Pico (RP2040), STM32, ESP8266 and ESP32 that supports different driver chips

github.com


Преимущества:
Поддерживает широкий спектр дисплеев, включая ST7789 (в т.ч. 170x320)
Хорошая производительность за счет использования аппаратного SPI
Совместима с STM32GENERIC-платформой (нужна настройка в User_Setup.h)
Много примеров, поддержка графики, шрифтов, кириллицы (UTF-8/CP1251 возможна через шрифты FreeFonts)
Гибкая настройка выводов, скорости SPI и особенностей контроллера
Инструкция по установке и настройке:
Установите библиотеку через менеджер библиотек Arduino IDE — найдите "TFT_eSPI от Bodmer".
В папке библиотеки откройте файл User_Setup.h.
Определите пины SPI, выберите драйвер ST7789, настройте размеры 170x320, цветовую инверсию и т.д., например:
// Вариант настроек (пример, корректируйте свои пины STM32)
#define ST7789_DRIVER
#define TFT_WIDTH   170
#define TFT_HEIGHT  320

#define TFT_MOSI PA7  // SDD  
#define TFT_SCLK PA5  // SCL  
#define TFT_CS   PA4  // CS
#define TFT_DC   PA3  // DC
#define TFT_RST  PA2  // RST

#define LOAD_GLCD       // Стандартный шрифт 8х8
#define LOAD_GFXFF      // Свободные шрифты (в т.ч. кириллица возможна в комбинации с FreeType)
//#define SUPPORT_TRANSACTIONS
Для поддержки кириллицы используйте расширенные шрифты или внедряйте свои bitmap-шрифты.
Примечание:

Если вы используете несколько плат/проектов, скорее всего, удобнее скопировать User_Setup.h в свой проект и перечислить нужные параметры.
Библиотека TFT_eSPI стабильно работает на STM32 под STM32GENERIC; при необходимости можно использовать альтернативу - Adafruit_ST7789 (но она менее производительно работает на STM32):
2. Альтернатива: Adafruit_ST7789

(Используется также для ST7789, совместима с STM32, но меньше возможностей кастомизации.)

Рекомендация:
TFT_eSPI — лучший выбор для STM32GENERIC + ST7789 + Arduino IDE.
Поддержка STM32 и множество настроек делают ее наиболее гибкой и производительной для вашего случая.

Ошибка

error: 'ltoa' was not declared in this scope
означает, что функция ltoa (long to ASCII) не определена для вашей платформы STM32/STM32GENERIC.
 Эта функция является нестандартной и не всегда поддерживается в компиляторах для Arduino, особенно на STM32.

Как исправить ошибку?
Вариант 1 — заменить ltoa на стандартную функцию sprintf:

Откройте файл TFT_eSPI.cpp, найдите строку вида:

ltoa(long_num, str, 10);
Замените ее на:

sprintf(str, "%ld", long_num);
или, что еще лучше (чтобы избежать проблем с размером знаковых/беззнаковых чисел):

snprintf(str, sizeof(str), "%ld", long_num);
Размер str
Убедитесь, что это нормально объявленный массив, например:

char str[12]; // для long этого достаточно
Вариант 2 — везде, где встречается ltoa, используйте sprintf:

sprintf(str, "%ld", long_num);
или через snprintf, как показано выше.

Причина:
ltoa есть на AVR-платах, но для STM32 и ряда других архитектур отсутствует.
sprintf и snprintf есть для всех платформ и стандартны для Си.
Кратко:
Найдите строку:

ltoa(long_num, str, 10);
Замените на:

sprintf(str, "%ld", long_num);
Если в библиотеке есть другие аналогичные вызовы (itoa, utoa и т.д.), их тоже заменяйте на sprintf/snprintf с нужным форматом (%d, %u, %ld, %lu и т.д.).

P.S.
После исправления сохраните файл библиотеки и пересоберите скетч — ошибка исчезнет.
