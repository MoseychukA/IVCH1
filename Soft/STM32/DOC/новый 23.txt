Рассуждения

192.168.75.1 — это почти всегда адрес роутера (gateway),а IP вашего устройства в этой сети должен быть вида 192.168.75.xxx.

Адрес 1.0.1.1 выглядит как “публичный DNS” (рядом с Cloudflare 1.1.1.1/1.0.0.1). Поэтому есть два типовых сценария:

DHCP запускается неправильно/ломает память,и в регистрах/структурах получаются “левые” значения → Ethernet.localIP()
 возвращает мусор вроде 1.0.1.1.
Вы на самом деле показываете не localIP,а DNS/GW,и потому видите 1.0.1.1.
Ниже — что сделать,чтобы точно исправить/диагностировать.

1) Исправьте DHCP-вызов Ethernet.begin() (самое важное)
У вас сейчас:

cpp Копировать
int ok = Ethernet.begin(mac[idx],&SPI_New,3000,1000);
В большинстве сборок Ethernet_Generic нет корректного DHCP overload с SPIClass*,а SPI выбирается через pCUR_SPI. Передача &SPI_New вторым аргументом часто приводит к неверному выбору overload/порче параметров → “левый IP”.

Исправьте в ДВУХ местах:

Impl::begin()
cpp Копировать
int ok = Ethernet.begin(mac[idx],3000,1000);
Impl::applyLanConfig()
cpp Копировать
int ok = Ethernet.begin(mac[idx],3000,1000);
2) Установите pCUR_SPI и поднимите SPI ДО Ethernet.init/begin
Сделайте одинаково в begin() и applyLanConfig():

cpp Копировать
extern SPIClass* pCUR_SPI;
pCUR_SPI = &SPI_New;

pinMode(USE_THIS_SS_PIN,OUTPUT);
digitalWrite(USE_THIS_SS_PIN,HIGH);

SPI_New.begin();
Ethernet.init(USE_THIS_SS_PIN);
Только после этого вызывайте Ethernet.begin(...).

3) Проверьте:вы не путаете IP устройства с GW/DNS
Сразу после Ethernet.begin(...) временно выведите:

cpp Копировать
SerialDebug.print("localIP="); SerialDebug.println(Ethernet.localIP());
SerialDebug.print("gw="); SerialDebug.println(Ethernet.gatewayIP());
SerialDebug.print("mask="); SerialDebug.println(Ethernet.subnetMask());
SerialDebug.print("dns="); SerialDebug.println(Ethernet.dnsServerIP());
Ожидаемо в вашей сети будет примерно так:

gw = 192.168.75.1
localIP = 192.168.75.xxx
dns может быть 192.168.75.1 или публичный (1.1.1.1,8.8.8.8 и т.п.)
Если окажется,что dns = 1.0.1.1,а localIP нормальный 192.168.75.xxx,то проблема не в 
Ethernet,а в том,что где-то в UI/NetFeed вы отображаете DNS вместо localIP.

4) Если после правки всё ещё 1.0.1.1
Тогда пришлите,пожалуйста,вывод 4 строк из пункта (3) и ваш код формирования NetConfig 
(где вы заполняете net.ip/net.dns/net.gw/net.mask из LanIfStore и вызываете ntpLan.begin(net) 
/ applyLanConfig(...)). По этим данным можно точно сказать,это:

неправильная маппинг-логика (GW/DNS/IP перепутаны),или
DHCP реально не поднимается (linkUp/maintain),или
SPI/CS не туда.
Но в 90% случаев именно замена Ethernet.begin(mac,&SPI_New,...) → Ethernet.begin(mac,...) убирает “IP = 1.0.1.1”.
